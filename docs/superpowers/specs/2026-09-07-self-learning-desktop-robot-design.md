# 自学习桌面机器人设计规格

- 日期：2026-09-07
- 状态：已确认（含开源复用清单）
- 路线：方案 2（便宜 Linux 板一体机）为主；必要时方案 1（ESP32 身体 + 手机/电脑大脑）过渡
- 落地顺序：先复用开源 Body（小智等）出体感 → 自研 Brain（记忆 + 技能权重）→ 再迁到 Linux 一体机

## 1. 目标与约束

### 1.1 目标

手搓一台「真正像机器人」的桌面陪伴机：有机身、语音对话、屏幕表情、简单舵机动作；具备可解释的自学习能力（记忆偏好 + 技能编排优化）；软件预留履带/轮式底盘升级，不推倒重来。

### 1.2 非目标（1 期内不做）

- 多自由度人形手臂/双足
- 默认本地大模型（仅预留同接口）
- 履带底盘与复杂导航（2 期）
- 昂贵麦克风阵列与深度强化学习训练管线

### 1.3 约束

- 预算：尽量压在 ¥500 以内
- 算力：云端 LLM 为主；预留本地模型适配器
- 部署：主路径为 Linux 小板一体；过渡路径为手机/电脑 Brain + ESP32 Body

## 2. 系统架构

三层分离，通信协议固定，便于方案 1 ↔ 2 切换。

```text
┌─────────────────────────────────────────┐
│  Brain（Agent 运行时）                    │
│  语音理解 → 规划 → 调工具 → 说话/表情/动作   │
│  部署：Linux 板（主）或 手机/电脑（过渡）     │
└───────────────┬─────────────────────────┘
                │  Body API（JSON；Wi‑Fi/串口或进程内）
┌───────────────▼─────────────────────────┐
│  Body（执行与感知）                        │
│  mic/TTS · 屏幕表情 · 舵机(转头/点头)      │
│  预留：摄像头 · 履带/轮式 Mobility          │
└───────────────┬─────────────────────────┘
                │
┌───────────────▼─────────────────────────┐
│  Memory & Learning（本地 SQLite）         │
│  用户偏好 · 对话摘要 · 技能成功率/失败原因   │
└─────────────────────────────────────────┘
```

### 2.1 关键约定

- Brain 只下发意图命令：`speak` / `set_face` / `look` / `move`（后期）
- Body 只回报结构化结果：`ok` / `fail` + 原因码
- 学习只更新记忆表与技能权重，不直接改硬件驱动参数（标定等走独立配置）
- 过渡期 Brain 与 Body 分机；主路径可进程内调用，**消息 schema 不变**

## 4. 自学习设计

第一版自学习为**可解释、可回滚**，不做端到端黑箱训练。

### 4.1 记忆学习（偏好）

- 存储：本地 SQLite 键值/事实表（如 `user.call_me`、`prefer.reply_short`）
- 写入来源仅限：用户明确陈述、用户纠正、用户确认「要记住吗」
- 规划前注入相关记忆；支持「忘掉 XXX」删除
- 冲突策略：新纠正覆盖旧值并打时间戳

### 4.2 技能编排学习（流程）

- 能力拆成可组合工具（例：`stt` → `llm_plan` → `set_face` → `look` → `tts`）
- 每次执行写 `SkillTrace`：意图标签、步骤序列、每步 ok/fail、耗时、用户反馈
- 权重规则：成功 +1，失败 -1 并记录原因；同意图优先高权重路径；接近时小概率探索
- 用户可查看数据库中的权重与轨迹，确认「学到了什么」

### 4.3 与感知—动作的关系（2 期）

- 1 期预留事件与 `move` 桩接口
- 2 期用同一套权重机制增加导航/循声类意图，不换学习框架

### 4.4 安全护栏

- 不自动执行危险或付费操作
- 记忆写入可配置为需确认
- 支持导出与清空学习数据

## 5. 软件模块与数据流

### 5.1 模块（Python）

| 模块 | 职责 |
|------|------|
| `sense` | 录音、VAD、STT |
| `brain` | 组提示词、调 LLM、产出工具计划 |
| `skills` | 工具：时间、天气、笔记、设偏好等 |
| `body` | Body API：`speak` / `set_face` / `look` / `move`(桩) |
| `memory` | SQLite：偏好、摘要、权重、轨迹 |
| `learn` | 根据轨迹与反馈更新权重与记忆 |
| `llm` | 云端 API 适配；预留本地（如 Ollama）同接口 |

### 5.2 单轮数据流

```text
听 → STT → 读记忆 → LLM 规划
  → 按权重选路径 → 逐步调 skills/body
  → 写 SkillTrace →（可选）确认是否记忆
  → learn 更新 → 表情回闲置
```

### 5.3 1 期 → 2 期升级

- `body.move`：空实现 → 履带/轮式驱动
- `sense`：增加摄像头事件上报（人脸/色块等）
- `learn`：增加导航类意图权重，机制不变
- Memory 库与 Brain 逻辑原样迁移到新外壳/底盘

## 6. 异常处理

- 网络/LLM 失败：困惑表情 + 本地兜底话术，保持听筒循环可恢复
- STT 空/乱：追问；连续失败则提示靠近麦并降敏
- 舵机/屏失败：记入失败原因；语音通道尽量保持；降低依赖该动作的路径权重
- 单步超时 3–5s，整轮有总超时；超时记 `fail`，禁止死循环重试
- 欠压（板支持时）：禁止猛打舵机，优先保语音

## 7. 测试与验收

### 7.1 测试分层

1. 单元：`memory`、权重更新、计划解析
2. 契约：假 Body（日志实现）跑通全流程（方案 1/2 切换前门禁）
3. 硬件冒烟：上电 → 听 → 说 → 表情 → 转头
4. 学习验收：纠正称呼后下次用对；故意失败后换路径

### 7.2 1 期验收标准

1. 上电能语音对话，屏有表情变化
2. 「看看我」类指令能转头/点头
3. 纠正称呼一次后，下次主动用对
4. 同类任务失败后更换备用路径，且权重可查
5. Brain 在板与电脑间切换时，Body 协议无需修改

### 7.3 日志

每轮 `session_id`；文本日志 + SQLite 轨迹。

## 9. 开源依赖与可复用清单

原则：**语音链路与机身交互尽量复用；Brain 的记忆 / 技能权重与 Body API 自研**，避免被单一固件绑死。

- Body API schema（`speak` / `set_face` / `look` / `move` + `ok`/`fail`）
- SQLite `memory` + `SkillTrace` + 技能权重更新（`learn`）
- `llm` 适配器（云端为主，预留 Ollama）
- 假 Body（日志实现）契约测试，保证方案 1↔2 可切换

### 9.5 许可与合规注意

- 复用前核对各仓库 LICENSE（MIT/Apache 等）及小智云端服务条款
- API Key、唤醒词与用户语音数据不进仓库；本地 SQLite 默认不上传
- 二次分发固件时保留原作者版权声明
