# 小小工坊：第二轮试玩与三维机架优化方案

日期：2026-09-22  
状态：试玩记录与后续设计建议；本文中的三维机架、物理系统和新挑战尚未实施。

## 1. 结论与目标

第二轮试玩确认：使用流程有所改善，第二关能够完成并正常领奖；但任务仍以扫描、拾取、返程为主，结构设计尚未影响解法。自动寻路停步和窄窗口界面重叠仍需排查。

下一步目标是“可拆装的机械结构 + 有物理反馈的桌面挑战”：让零件的位置、连接与质量真正影响运动、稳定性和任务结果，形成装配、试跑、观察失败、修改和再次尝试的循环。

当前画面已经使用 Three.js 渲染三维场景。“完整三维机架”意味着升级结构表达、装配交互和运动模拟，而不只是替换更精细的外观模型。

## 3. 当前版本优先优化

### P0：寻路与界面

自动寻路虽已拆分为独立模块，但不能以模块存在或单元测试通过作为问题已解决的证据。应联查 `game.js` 的移动调用、路径取消版本、忙碌状态，与 `scene.js` 的动画完成通知。记录每一步的开始、完成、取消与失败原因；排查浏览器可见性变化的影响。

验收：一次点击完成空旷路径及绕障路径；转向后继续前进；新目标或方向键能按约定接管；不可达或请求失败有提示；不静默停步。

窄窗口应为固定顶栏预留真实空间，任务面板支持收起并保留当前目标摘要。检查页面滚动后的定位，而不只检查初次打开的位置。

验收：在本次截图尺寸、常见桌面窗口和手机竖屏下，品牌、任务、资源、操作按钮互不遮挡；收起与展开后均能操作。

### P1：新手与任务变化

- 推荐装配：继续测试缺零件、功耗不足、需要卸装和已满足方案四种状态；预览与实际结果一致，不自动购买。
- 第二关变化：增加不同于首关的空间问题，例如窄缝取物、坡道搬运或抽屉取物。
- 独立试验场：无需接委托即可验证作品，并能快速复位和返回编辑。
- 结构反馈：玩家改装后必须能感知行为差异，避免仅改变外观或能力标签。

## 4. 三维机架产品方案

| 层次 | 改造内容 | 玩家收益 |
| --- | --- | --- |
| 结构 | 底板、横梁、支架、电机、轮轴、关节、工具、外壳拆分 | 能理解机器人由什么组成 |
| 编辑 | 重复零件、吸附、旋转、镜像、撤销、选中高亮、爆炸视图 | 能创造不同结构 |
| 运动 | 关节轴、角度限位、目标速度、驱动力限制 | 机械臂围绕连接处运动，有合理范围 |
| 物理 | 质量、惯性、重心、摩擦、碰撞和约束 | 结构选择产生稳定性、通行与搬运差异 |
| 环境 | 方块、抽屉、坡道和门参与碰撞或关节运动 | 推、夹、拖、顶成为可选方法 |
| 表现 | 金属、橡胶、塑料材质；电机与碰撞音效 | 增强重量感和机械感 |

外壳支持隐藏或半透明查看机架。爆炸视图仅用于编辑展示，不能直接改变保存的结构或模拟状态。

真实感以帮助理解和创造为目标。首版不要求每颗螺丝、每根线缆或每节履带独立模拟，也不以工程级精度、可制造性或真机安全性作为游戏模拟的默认承诺。

## 5. 技术路线与数据边界

### 5.1 保留基础，先做物理原型

建议保留 Three.js 渲染和 Python 存档服务，验证 Rapier 浏览器物理引擎。此为候选方案，必须通过关节稳定性、加载兼容性与目标设备性能原型后再锁定版本。

- Three.js：加载 GLB 零件、相机、材质、灯光、选择与编辑辅助。
- Rapier：刚体、碰撞体、关节和物理步进。
- Python：零件目录、蓝图校验、版本迁移、存档和任务进度。
- 浏览器控制层：把输入转换为驱动目标，再将模拟结果同步到画面。

参考官方能力说明：[Three.js GLTFLoader](https://threejs.org/docs/pages/GLTFLoader.html)、[Rapier 刚体](https://rapier.rs/docs/user_guides/javascript/rigid_bodies/)、[Rapier 碰撞体](https://rapier.rs/docs/user_guides/javascript/colliders/)、[Rapier 关节](https://rapier.rs/docs/user_guides/javascript/joints/)。这些资料支持技术能力判断，不代表本项目已经接入。

### 5.2 蓝图作为装配事实来源

编辑器、三维画面和物理世界都从同一份蓝图生成，逐步替换当前按 `equipped` 切换固定模型显隐的流程。

| 数据 | 至少包含 |
| --- | --- |
| 零件定义 | 视觉资源、简化碰撞形状、尺寸、质量、连接点、材料与能力 |
| 零件实例 | 唯一 ID、定义 ID、局部位姿、可编辑参数 |
| 连接 | 父子实例、连接点、关节类型、轴、限位及驱动配置 |
| 蓝图 | 实例集合、连接集合、根实例、输入绑定、版本 |
| 模拟状态 | 位置、朝向、速度、关节状态、抓取状态与任务检查点 |

统一使用米、千克、秒，明确游戏坐标系；局部旋转必须正确参与父子变换。游戏蓝图与工程 CAD／机器人描述之间通过显式转换衔接，不能仅因名字相同就共用单位或坐标约定。

编辑状态与运行状态分离：运行时停止直接拖改活动刚体；返回编辑先暂停模拟，结构改变后重建必要刚体与约束。对不再有效的抓取关系和检查点给出明确处理规则。

### 5.3 视觉与物理解耦

GLB 可以包含倒角、螺丝、外壳和线缆细节。动态碰撞优先采用盒体、圆柱或凸形组合，并单独校验碰撞形状与外观尺寸是否匹配。

固定机架合并为一个刚体及多个碰撞体；需要相对运动的部分再拆为独立刚体。防止质量或惯性重复计算，避免相邻连接件不必要的自碰撞。运行时由物理状态驱动画面，不同时由动画和物理争夺同一部件的位置。

采用固定物理步长和渲染插值；暂停、后台恢复时限制追赶计算量。具体步长、求解精度和零件预算依据原型测试确定。

### 5.4 连续运动与抓取

方向输入控制速度或轮子驱动，物理接触决定实际移动。点击目标作为导航意图，不能继续把机器人直接移到下一格。新导航需考虑机架尺寸、转弯空间及当前动态障碍。

抓取检查可达范围、夹爪方向和接触条件。首版可使用辅助吸附与可释放的抓取约束，以保持可玩性，但应让玩家知道辅助发生的时机。目标进入交付区域后判定任务完成，避免只检查指定配件是否存在。

浏览器高频模拟不逐帧请求 Python。后端保存蓝图和检查点；如果将来增加公开排行榜，需要单独设计成绩验证，不能将客户端上报直接视为可信竞赛结果。

## 6. 最小可玩原型与交付顺序

### 阶段一：修复现有体验

完成寻路、窄窗口布局回归以及推荐装配四种状态验证，保留旧任务与存档可用性。

### 阶段二：三维机架与编辑

提供一台四轮机架、一条两关节机械臂及夹爪。支持连接点装配、零件重复使用、旋转、撤销和保存。验证实例与连接在重载后保持一致。

### 阶段三：物理试验场

提供平地、坡道、窄门和可搬方块。接通驱动、碰撞、关节限位和抓取；提供复位和失败原因辅助。先确保基础机器稳定可控，再增加材质与音效。

### 阶段四：一个多解挑战

完成“抽屉取物并运回工坊”，分别支持夹取、推送、拖拽。保存作品与挑战结果，再依据玩家反馈决定新增关卡或分享功能。

## 7. 验收标准

- [x] 加长机械臂能扩大实际可达范围；关节旋转正确围绕连接轴进行。（自动化：`buildSimFromBlueprint` reach 度量，见 `tests/test_game_phase2_acceptance.mjs` / `test_game_sim_body.mjs`）
- [x] 搬起重物会影响稳定性，且原因能被玩家观察理解。（自动化：`checkTip` 倾覆与 reason，见 `tests/test_game_sim_body.mjs`）
- [x] 加宽底盘改善抗翻，同时可能无法通过窄门。（自动化：宽底盘 `width > door.width`、窄底盘 `<`，见 `tests/test_game_phase2_acceptance.mjs`）
- [ ] 机器人、工具、物体与环境不会在正常操作下明显穿透。
- [x] 同一挑战有至少三种机制不同的成功方案。（自动化：grasp / push / drag 各报 success，见 `tests/test_game_phase2_acceptance.mjs` / `test_game_challenge_mechanics.mjs`）
- [x] 失败后可以快速复位，返回编辑后不丢失作品。（自动化：`enter_yard` / `exit_yard` 保留蓝图，见 `tests/test_game.py`）
- [x] 保存重载保持结构和控制绑定；旧存档迁移保留已有进度。（自动化：`blueprint_replace` 与 v2→v3 迁移，见 `tests/test_game.py`）
- [ ] 在约定设备和零件规模下测量帧耗时与物理稳定性；性能目标在测试前明确，不以开发机表现代替全设备结论。
- [ ] 小规模玩家测试观察是否主动改第二版、尝试另一种解法，以及是否理解失败原因。

## 8. 风险与控制

| 风险 | 控制方式 |
| --- | --- |
| 结构越来越细，模拟抖动或变慢 | 合并固定结构、简化碰撞、设置并测试零件预算 |
| 画面更真实但玩法仍重复 | 每个结构参数对应一个可感知的行为取舍，用多解挑战验证 |
| 装配操作过于专业 | 吸附、推荐模板、镜像、撤销、可视限位和渐进引导 |
| 模型与物理尺寸不一致 | 建立资源规范并验证单位、原点、连接点和碰撞形状 |
| 物理失败难以理解 | 展示重心、接触和关节限位等可切换辅助信息 |
| 新旧运行机制相互覆盖 | 保留兼容模式，蓝图编辑与物理试验明确分阶段接入 |
