# 小小工坊：实际试玩评估与优化清单

日期：2026-09-21  
状态：优化建议，尚未实施。本文记录一次实际试玩，不能代替玩家留存测试或完整兼容性测试。

## 1. 评估结论与范围

当前版本能够完成装配、任务、改装、交付和奖励流程。暂停后的改装阻塞在本次试玩中没有复现，但固定位置的零件装卸和重复搬运任务，仍不足以形成持续尝试的动力。

本次在本机 `http://127.0.0.1:8878/` 使用独立测试存档，通过浏览器实际操作完成第一关，并查看第二关解锁结果。试玩窗口截图约为 653 × 762 像素；界面重叠结论仅对应这次窗口，其他尺寸待验证。

实际路径：

1. 安装摄像头，尝试安装右机械臂，触发供电超限提示。
2. 卸下表情屏幕，安装右机械臂，供电达到 12 / 12 W。
3. 点击“开始试运行”，进入委托板并接受第一关。
4. 点击远处目标尝试自动寻路，随后使用方向键靠近目标。
5. 完成扫描和拾取，在携带核心期间返回改装。
6. 卸下右机械臂、安装左机械臂，恢复原任务。
7. 返回充电站并交付，获得 80 零件币、30 默契，第二关解锁。

未完整试玩第二、三关，未进行长时间性能、移动端触控或真实玩家留存测试。本文不据此推断热门榜潜力。

## 2. 已验证有效的体验

| 项目 | 本次结果 | 后续需要保持的行为 |
| --- | --- | --- |
| 暂停后改装 | 可以卸下右臂并安装左臂 | 返回改装后立即明确显示暂停状态，允许合法改装 |
| 任务恢复 | 换臂后可以继续，扫描和携带状态保留 | 保留进度；装备不满足恢复条件时给出具体说明 |
| 功耗提示 | 14 W 超过 12 W 时，提示卸屏幕或扩容 | 显示差额和可行解决方法，不能只报失败 |
| 通关与奖励 | 首关交付成功，奖励和第二关解锁正常 | 保持奖励、任务完成状态和解锁结果一致 |

## 3. P0：先修复操作与显示问题

### P0-01 自动寻路疑似中断

**观察：** 多次点击远处核心或充电站后，步数只增加一步，机器人停下；最终通过方向键完成返程。此为本次试玩观察，尚未定位根因，不应直接认定路径算法错误。

**影响：** “点击桌面自动寻路”的承诺与操作结果不一致，玩家容易重复点击，误以为选点无效。

**排查方向：** 检查路径循环、移动请求返回值、忙碌状态、动画完成信号和路径取消条件；同时检查点击位置与地面格子的映射。区分正常转向等待、主动取消和意外中断。

**验收：**

- [ ] 空旷路径和绕障路径均可一次点击连续抵达，不需逐格重复点击。
- [ ] 转向完成后继续前进，朝向与位移一致。
- [ ] 点击新目标、方向键介入和离开任务页面时，旧路径按明确规则取消。
- [ ] 不可达目标或请求失败时有明确提示，不静默停下。
- [ ] 连续完成一次去程和一次返程，并核对位置、步数与电量。

### P0-02 窄窗口任务面板与顶栏重叠

**观察：** 本次窄窗口截图中，左上任务说明与品牌标识重叠，任务标题与部分说明受到遮挡。

**影响：** 玩家难以辨认当前目标，界面遮挡削弱场景可读性。

**优化：** 为顶栏预留布局空间；任务面板可收起，只保留当前步骤；检查底部操作栏与导航的间距。

**验收：**

- [ ] 在本次窗口附近尺寸、常见桌面窗口和手机竖屏尺寸分别检查。
- [ ] 标题、当前目标、资源和关键操作无重叠、无裁切。
- [ ] 收起面板后保留任务入口，不遮挡关键场景交互。
- [ ] 面板展开、浏览器缩放及窗口变化后，布局仍可用。

## 4. P1：改善新手流程与核心玩法

| 编号 | 观察或设计判断 | 优化方向 | 验收标准 |
| --- | --- | --- | --- |
| P1-01 | “开始试运行”实际进入委托板，入口语义不符 | 短期改为“前往委托板”；试验场完成后提供独立试运行入口 | 按钮名称与实际落点一致；试验场无需接取委托即可进入 |
| P1-02 | 首关按任务要求加装摄像头和机械臂时先遇到供电不足 | 提供可运行的推荐装配与一键应用；首次成功后逐步引入预算取舍 | 新玩家能看懂如何出发；保留手动调整，并清楚显示调整结果 |
| P1-03 | 玩家仍只能固定位置装卸零件，缺少自主设计空间 | 支持重复零件、位置与方向调整、连接吸附、选中高亮、撤销和蓝图保存 | 用同一组零件造出至少三种结构；保存重载后位置与连接一致 |
| P1-04 | 首关左右臂互换未带来明显解法变化 | 将臂长、轮距、工具朝向与可达范围、通行和稳定性连接起来 | 改变结构会产生可观察、可解释的行为差异，界面能够帮助定位失败原因 |
| P1-05 | 首关完成后，第二关介绍仍是搬回另一枚核心；重复感为设计判断，第二关未完整试玩 | 引入窄缝取物等新问题，允许夹取、推送或拖拽 | 同一目标能由三种机制不同的方案完成，不要求唯一指定零件组合 |

推荐装配涉及装备、货币或任务进度变化时，应先展示结果，避免不透明地自动购买零件。

## 5. 下一版最小可玩目标

集中完成“自由装配试验场 + 抽屉取物挑战”，暂缓批量增加同类搬运任务。

**挑战：** 将抽屉中的方块运回工坊。

**三条候选解法：** 长臂夹取、推板推送、吊钩拖拽。场景需为每种方法提供合理操作空间，以实际运动和目标到达判定成功，而非检查玩家是否装上指定配件。

**体验循环：** 装配 → 试跑 → 看懂失败 → 小幅修改 → 再试 → 成功 → 保存作品。

首轮至少让玩家体验一种明确的结构取舍，例如加长机械臂扩大可达范围，但降低稳定性；加宽底盘改善稳定性，却可能无法通过狭窄通道。具体数值需要试玩调节，不在本报告中视为已确定。

**交付顺序：**

1. 修复寻路和布局，复测首关完整流程。
2. 修正入口文案和新手装配引导。
3. 接通蓝图编辑、场景显示和实际行为，提供独立试验场。
4. 完成一个多解挑战，加入快速重试、蓝图保存和用时／零件数记录。
5. 再根据试玩反馈决定是否扩充关卡、作品分享或成长系统。

## 6. 复测与玩家验证

技术回归应覆盖：暂停与恢复、携带中换臂、功耗超限、路径取消、交付奖励、旧存档读取以及窄窗口布局。自动化逻辑测试不能替代完整浏览器试玩。

建议邀请 10–20 名目标玩家进行小规模验证，分别记录：

- 首次成功需要多久，以及在哪一步需要帮助。
- 是否理解零件位置和结构对行为的影响。
- 失败后是否主动修改，修改是否针对失败原因。
- 是否自发尝试第二种解法，或愿意展示自己的作品。
- 离开时的原因，以及之后是否愿意再次体验。

这些是下一轮观察指标，不是行业通用热门门槛。先记录基线，再设改进目标；目前没有足够数据预测留存或榜单表现。
