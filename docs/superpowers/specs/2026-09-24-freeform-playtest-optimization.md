# 小小工坊：第三轮自由装配试玩与优化方案

日期：2026-09-24  
状态：实际试玩记录与待实施建议。疑似根因未经修复后回归确认，不视为最终诊断。

## 1. 结论

项目已经提供自由装配、四轮模板、蓝图保存、试验场和抽屉挑战入口，比此前的固定装备切换有实质进展。但本轮试玩出现模板应用结果未保留、进入试验场后缺少工具的问题，阻断了“装配—试跑—修改”的核心流程。

近期目标：玩家修改一处结构，保存后能原样带进试验场，并看见对应的行为变化。先保证作品可靠保存和可操作，再扩充零件、关卡与外观细节。

## 2. 试玩范围与证据

使用本机 `http://127.0.0.1:8878/`，独立存档目录 `/tmp/robot-playtest-20260924`。通过浏览器界面操作，未直接修改游戏状态以跳过流程。截图窗口约 664 × 762 像素。

实际路径：

1. 从首页进入自由装配；一次进入后观察到页面返回传统改装，随后从面板重新进入。
2. 应用四轮模板，出现“已应用四轮+臂模板（记得保存）”提示。
3. 点击保存，出现“蓝图已保存”提示。
4. 进入试验场，尝试 W、E、Space 操作。
5. 抓取操作提示“蓝图上没有夹爪/推板/钩子”。
6. 开始抽屉挑战，显示运送方块到接收区的目标。
7. 返回编辑，再次应用模板并查看画布，未看到完整四轮机械臂结构。

本次确认的是入口、提示和上述异常。按过驾驶和关节键不等于已验证正常运动；因工具与模板状态异常，未完成抽屉挑战，也未重新通关旧委托。此前的自动寻路问题本轮未复测，不能认定已修复。

## 4. P0：保证作品不丢失

### P0-01 模板、保存与试验场结构不一致

**复现步骤：** 独立存档 → 自由装配 → 应用四轮模板 → 保存蓝图 → 进入试验场 → Space 抓取。

**预期：** 四轮、机械臂和夹爪随蓝图进入试验场；无可抓物体时提示距离或目标问题。

**实际：** 提示已应用和已保存，但试验场提示没有任何工具；返回编辑再次应用模板后，画布仍未保留完整结构。

**影响：** 玩家不能信任保存结果，无法判断是自己的装配错误还是系统问题。这是当前最优先的体验阻断。

**排查与改造：**

- 分别记录应用模板后、保存请求前、保存响应后、进入试验场时的蓝图 ID、修订号、实例 ID 和连接集合。
- 区分编辑草稿、已保存版本和试跑快照，禁止一般界面刷新无声覆盖草稿。
- 保存响应只更新对应版本的保存状态；保存期间若允许继续编辑，旧响应不能覆盖新修改。
- 进入试验场使用明确的蓝图版本，并在失败时保留编辑内容与具体原因。
- 增加可见的作品名、零件数和“未保存／保存中／已保存／失败”状态。

**验收：**

- [ ] 四轮模板的 10 个实例、9 条连接在编辑、保存与试验场之间一致。
- [ ] 模板中的 `gripper-1` 可被试验场识别，不能再提示缺少工具。
- [ ] 保存后刷新，结构、局部位姿与连接保持一致。
- [ ] 保存失败不清空草稿，能明确重试。
- [ ] 返回编辑恢复作品，不把试跑中的姿态意外写入结构。

### P0-02 普通点击疑似触发重新导航

代码检查发现 `game.js` 使用 `e.target.closest('[data-view]')` 处理全局点击，而 `body` 同样设置了 `data-view`。因此普通操作可能匹配页面本身并重新进入当前页面；编辑器初始化又可能从存档重新同步蓝图，覆盖未保存草稿。

这条调用链与试玩现象相符，但尚未通过运行日志或修复前后对照完成根因确认。不要仅凭推断宣布问题解决。

**建议：**

- 导航事件仅接受明确导航控件，例如专用 `data-nav` 或受限容器内的按钮。
- 同页导航不应重新初始化编辑草稿；显式“重新载入”单独处理。
- 初始化、恢复存档、编辑操作和保存响应分别负责自己的状态变更。
- 离开未保存作品时保留草稿，或提供保存／保留／放弃选择。
- 保存不应清空撤销历史；设置保存检查点以判定是否还有未保存修改。

**验收：**

- [ ] 点击模板、零件、连接点、画布、保存、撤销和重做均不会触发非预期导航。
- [ ] 应用模板后继续选零件或旋转视角，实例数不变。
- [ ] 保存前后的撤销与重做行为连续可预期。
- [ ] 离开、返回以及快速切换页面均不会无提示丢失作品。

## 5. P1：让玩家看清、操作并理解作品

| 问题 | 改造方案 | 验收标准 |
| --- | --- | --- |
| 窄窗口首屏几乎全是零件列表，画布在下方 | 画布常驻，零件库折叠或横向排列；复杂参数按需展开 | 选择零件与查看连接点无需反复滚动 |
| 试验场机器人很小，轮子与工具难辨认 | 按模型包围盒自动取景；加入聚焦、缩放和跟随模式 | 正常窗口可辨认车轮、关节、工具和目标；不会被控制面板遮挡 |
| 没有工具仍可启动抽屉挑战 | 启动前检查实际蓝图是否可驱动、是否有可用操作工具 | 缺项能跳转到对应编辑步骤；允许不同工具解法，不锁死唯一装备 |
| 驾驶、关节和抓取反馈不够清楚 | 显示当前工具、受控关节、操作范围和失败原因 | 无目标、距离过远、朝向不对、限位分别提示 |
| 编辑与试跑之间缺少作品身份提示 | 显示当前作品、零件数、保存状态和试跑版本 | 玩家能确认试跑的是刚才编辑的机器 |

## 6. P2：用结构反馈验证可玩性

先完成一个稳定的物理试验和一个多解挑战，再扩充内容。

- 加长机械臂扩大实际可达范围，同时可能降低稳定性。
- 加宽底盘改善抗翻，但可能无法通过窄门。
- 搬起更重的物体影响运动或稳定性，失败原因应能理解。
- 坡道接通物理前保持清楚标注，不能把视觉占位当作已完成试验项目。
- 抽屉取物支持夹取、推送和拖拽，通过物体结果判定成功。
- 失败后快速复位，返回编辑保留作品，让玩家愿意主动再改一次。

验收不以“存在按钮或模块”为准，而以玩家能完成从构想到试跑的行为为准。

## 7. 实施顺序与回归清单

### 第一阶段：作品可靠性

定位导航与状态覆盖问题；分离草稿、保存版和试跑快照；补充模板—保存—进入—返回—刷新链路测试。保留原有存档兼容性，不通过清空存档掩盖问题。

### 第二阶段：可操作的四轮机械臂

调整布局和镜头；完整显示模板；确认驾驶、关节、抓取、释放、复位与回编辑均可用。普通点击、按键焦点和页面滚动不能干扰编辑或驾驶。

### 第三阶段：可重复尝试的挑战

完成抽屉取物的三种解法，验证成功判定和结算，再邀请少量目标玩家观察是否主动修改第二版、是否能解释失败原因。

**发布前回归：**

- [ ] 新存档：模板应用、保存、试跑和返回编辑完整通过。
- [ ] 手动装配：重复零件、连接、撤销／重做及刷新恢复通过。
- [ ] 异常：保存失败、快速切页、连续点击不丢作品。
- [ ] 试验场：驾驶、关节、工具、复位、扶正和挑战结算通过。
- [ ] 布局：本次窄窗口附近尺寸与常见桌面尺寸均可操作。
- [ ] 旧玩法：推荐装配、自动寻路、暂停改装和首关交付重新验证。
