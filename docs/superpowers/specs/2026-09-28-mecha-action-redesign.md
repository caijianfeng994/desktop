# 小小工坊：自由装配与第一人称机甲动作游戏改造方案

日期：2026-09-28  
状态：实施中（2026-09-28）。已落地：机甲零件/工程机甲模板/程序化外形、战斗与巡逻敌、书架救援挑战与掉落库存、绞盘/推进模块、区域与视野提示。验收清单与三解法联检持续补齐。

## 1. 产品方向与参考边界

目标是将桌面机器人装配试玩升级为轻量机甲动作游戏：在巨大化的房间废墟中，驾驶自己设计的机甲，进行立体探索、战斗、救援和部件回收。

参考《机甲战魔 神话之裔》的装甲与武器组合、机动战斗、装备获取和流派构筑。第一人称驾驶、基础件自主设计和房间尺度冒险是本项目的方案，不作为对参考游戏功能的描述。

此前查阅的官方资料：

- [官方改装说明](https://jp.daemonxmachina.com/titanicscion/system/customize/)：装甲组合影响性能，武器与附件形成配置，探索与战斗提供装备或设计图，也支持外观定制。
- [官方动作说明](https://jp.daemonxmachina.com/titanicscion/system/)：立体机动、近远程兵装及不同战斗方式。

采用原创机体、世界、美术和任务，借鉴的是体验原则。首版以一个可反复玩的完整战场验证方向，不以大型开放世界、联机或数百件装备作为前置条件。

## 2. 核心体验与成长循环

发现目标 → 设计机体 → 组装与试跑 → 出击 → 战斗／救援／探索 → 回收部件与设计图 → 改装 → 到达新区域。

三个核心承诺：

1. 我能决定机器的结构和控制，而不仅是选择成品装备。
2. 换底盘、手臂、背包或武器后，外形和打法都会变化。
3. 新部件提供新的行动方式，让我有理由继续探索和改装。

温暖工坊保留为基地，出击区域强调高度、风险、速度与判断。长期追求是拥有不同用途的自制机体，并用它们进入此前不可达的区域。

## 3. 第一人称与机体展示

第一人称必须能完成移动、战斗与工具操作；第三人称承担装配展示和可选探索视角。镜头切换是体验选择，不应因任务强制切换打断瞄准。

| 场景 | 推荐视角 | 设计目的 |
| --- | --- | --- |
| 工坊装配 | 第三人称环绕、标准视图 | 看清轮廓、关节、挂点和配色 |
| 自由探索 | 第三人称跟随，可切驾驶舱 | 观察地形与自己设计的机体 |
| 战斗、瞄准、工具操作 | 可持续使用第一人称驾驶舱 | 提供临场感和精确操作 |
| 终结或损伤展示 | 可选短外部镜头，可跳过 | 展示机体动作和结构变化 |
| 作品收藏 | 第三人称摄影 | 保存和欣赏自己的设计 |

驾驶舱显示能源、热量、弹药、锁定目标、受损部位和工具状态。不同机体配置改变相关显示及可见手臂／武器，不能只叠加一张固定遮罩。

第一人称实现要求：

- 相机挂在专用稳定节点，避免直接继承步行动画造成晕动。
- 视角范围、灵敏度、镜头震动和动态视野可调整；受击反馈不遮蔽关键目标。
- 瞄准方向与武器枪口碰撞分开检查，解决近墙射击和准星视差。
- 自制装甲不能无提示遮住驾驶视野；编辑时提供视野预览。
- 处理机体自遮挡、近裁剪、工具接触点和切镜连续性。

## 4. 自由装配与外形变化

采用“结构、功能、外观”三层，但共用同一蓝图。

| 层 | 玩家选择 | 结果 |
| --- | --- | --- |
| 结构 | 板、梁、关节、轮组、轴与支架 | 决定轮廓、尺寸、连接和运动范围 |
| 功能 | 动力、推进、能源、散热、武器、工具 | 决定移动与战斗能力及预算 |
| 外观 | 装甲造型、配色、贴花和发光件 | 表达个人风格并保持功能可辨认 |

主装配区域为核心、头部、躯干、左臂、右臂、腿部／底盘、背包、左肩挂点和右肩挂点。它们是组织与兼容接口，不要求每个区域只能安装一个成品模块；区域内部允许基础件组合和自制组件。

玩家可以从空机架开始，也能拆开模板修改。支持重复零件、连接吸附、旋转、有限尺寸调整、镜像、撤销、控制绑定和组件复用。复杂闭环机构待求解能力成熟后开放。

每个模块包含连接点、尺寸、质量、供电、散热、耐久、碰撞与活动轴等相关数据。装配预览显示接口、运动范围、穿插和预算问题。模块保存为独立版本，修改一个实例不应意外改变其他作品。

外形变化必须真实可见：履带与双足有不同轮廓和动作，长臂与重甲改变占地，背包和肩部武器显示在对应挂点。纯涂装可以独立于性能；显著改变尺寸或装甲覆盖的造型需遵守碰撞与命中一致性，不能用外观覆盖隐藏实际命中范围。

## 5. 机体流派与取舍

| 流派 | 外形特征 | 优势 | 代价 |
| --- | --- | --- | --- |
| 轻型侦察 | 窄躯干、轻甲、小型推进组件 | 快速探索和脱离 | 防御与载荷有限 |
| 重型突击 | 宽装甲、重底盘、炮架 | 承伤与重火力 | 转向、能耗和通行受限 |
| 工程救援 | 长臂、夹爪、绞盘、维修模块 | 搬运、牵引、救援 | 正面火力较弱 |
| 空中游击 | 轻甲、推进背包、翼板 | 短时飞行和高处攻击 | 燃料、热量与落点压力 |
| 近战格斗 | 刀臂、盾牌、强化移动组件 | 贴身爆发和防御反击 | 接近风险与射程限制 |

首个版本先验证地面工程机体和基础远程战斗；其余流派逐步加入。质量、动力、热量、供能与防御形成明确取舍，数值经试玩调整，避免纯粹“高等级零件全面更强”。

## 6. 战斗、立体空间与任务

场景使用实际高度差、坡道、桌缝、书架、吊灯、抽屉和掩体。移动由连续控制与碰撞反馈决定；导航只提供方向或目标，不直接传送到格子。

首版战斗包含一类有预警攻击的敌人、一种远程武器和一种工具或近战装备。建立瞄准、命中、受击、热量／弹药、敌人反馈与失败重试闭环，再扩展锁定、推进、盾牌和部位破坏。

可选任务类型包括救援、夺取核心、摧毁炮塔、护送与回收。任务按实际目标结果判定，不将某个唯一零件作为通关钥匙。风险需要可预判，失败可快速重试，作品不能丢失。

部件损伤初期可降低功能或表现损坏；可脱落结构放到后续阶段，需同步更新连接图、碰撞和控制绑定，避免引入不稳定状态。

## 7. 首个可玩战场：书架救援

目标体验长度暂以约十分钟为设计参考，实际时长通过试玩测量。

一台维修机器人困在倾斜书架上，地面有巡逻敌机。玩家从机库出发，绕开或击败敌人，到达救援点并带回目标，获得新部件或设计图。

分步交付：

1. 地面路线：四轮工程机甲通过坡道与掩体，完成射击和抓取救援。
2. 牵引路线：加入绞盘和锚点，验证另一种结构解法。
3. 高处路线：加入短时推进和落点挑战，形成第三种解法。

推进器、牵引和破坏路线不必同时进入第一版。首个闭环完成后，新部件应开启一个清楚可见的新机会，例如此前无法到达的平台。

## 8. 技术迁移与模块职责

现有蓝图、编辑器、Three.js 场景和 Python 服务作为候选基础。历史报告反映过草稿覆盖与试验场不同步，实施前需要复测当前版本，不能把旧报告当作当前代码诊断。

| 模块 | 改造职责 |
| --- | --- |
| 蓝图与资源目录 | 结构、挂点、运动轴、武器、驾驶舱配置、材质和输入绑定 |
| 编辑器 | 机库装配、镜像、碰撞预览、视野、预算及重心检查 |
| 渲染与相机 | 外部机体、驾驶舱、切镜、遮挡与模型表现 |
| 控制与模拟 | 连续移动、关节、工具、武器命中、受损与复位 |
| 敌人与任务 | 敌人决策、目标状态、奖励、回收与区域解锁 |
| 存档 | 多机体蓝图、库存、设计图、配色和冒险进度 |

设计态、运行态与表现态分离：蓝图决定结构；运行状态记录速度、关节、热量和损伤；渲染读取两者，不能反向覆盖草稿。高频运行放在客户端，Python 管理持久化与规则校验。未来公开竞争成绩需另行设计可信验证。

先做机体规模、碰撞、相机和战斗原型，再确定是否继续现有浏览器路线。若目标设备性能或资源制作流程不满足要求，再比较引擎迁移成本；本文不默认必须重写或新增特定引擎。

机械动作兼顾可控性：首版可使用稳定的底盘控制与动画配合碰撞，避免把整台活动机体直接当作松散刚体链。视觉上的轮轴、关节和接触必须与实际动作一致。

## 9. 分阶段实施与验收

| 阶段 | 交付 | 验收重点 |
| --- | --- | --- |
| 0：作品可靠 | 模板、草稿、保存、运行快照与迁移 | 编辑、刷新和试验场中的结构一致 |
| 1：机库与驾驶 | 四轮工程机体、外形变化、第一／第三人称切换 | 可看清、驾驶、抓取并完整恢复作品 |
| 2：基本战斗 | 一类敌人、一把远程武器、工具、受击与重试 | 第一人称下完成一场有判断的战斗 |
| 3：救援闭环 | 立体战场、救援、掉落、改装与新区域机会 | 获得部件后有明确继续玩的理由 |
| 4：流派扩展 | 绞盘、推进、重甲等不同方案 | 同一目标至少三种机制不同的解法 |
| 5：内容扩展 | 新敌人、首领、区域、作品展示 | 按真实玩家反馈选择投入方向 |

阶段门槛以完整可玩行为为准，不以按钮、文件或零件数量计算完成度。首版不要求开放世界、联机、数百件装备或全部损伤脱落系统。

## 10. 验证清单与风险控制

- [ ] 玩家能从基础件修改或设计机体，组件可保存并复用。
- [ ] 换底盘、手臂、背包或武器后，轮廓和实际行为都改变。
- [ ] 第一人称能完成移动、瞄准、战斗、抓取和任务交付。
- [ ] 切换视角不改变实际位置、命中结果和输入状态。
- [ ] 自制结构不无提示遮挡视野；近墙射击和工具接触判定合理。
- [ ] 热量、能源、受击与损伤的反馈一致，镜头震动可减少。
- [ ] 保存重载、失败重试和换装不丢失作品或重复奖励。
- [ ] 约定目标设备、分辨率、机体零件数和敌人数量后测量性能，不提前承诺全设备帧率。
- [ ] 小规模玩家测试观察是否主动改装再战、能否解释配置取舍、是否期待新部件。

主要风险是范围扩张、自由结构与动画兼容、第一人称晕动、复杂碰撞性能以及美术资源工作量。通过限定原型规模、统一挂点规范、提供视野预览、合并固定结构和逐阶段验收控制风险。
