# 小小工坊：真实 3D 游戏体验改进方案

日期：2026-09-24  
状态：已实现（2026-09-28 对照 §9 落地）。装配预览/碰撞确认、机械外观、抓取全过程、试验场防穿墙、结构对比、画质分档与调试叠加已接线；验收项见 §9 勾选。

## 1. 问题与目标

用户反馈：画面不像 3D 游戏，希望获得接近真实的体验。

当前已有三维渲染，但远距离镜头、占据较大空间的网页面板、平面化通行、简化结构和不充分的接触反馈，使机器人更像网页中的展示模型。第三轮试玩还暴露模板与保存状态不一致的问题，必须先解决，才能评估完整机器的表现。

改造目标：采用“真实机械 + 温暖房间”的方向，让玩家相信机器有尺寸、重量、连接和动力，并能亲手设计、驾驶、抓取和修改。

真实感不是单纯增加多边形、变暗画面或添加磨损，而是视觉、声音和交互对同一物理行为给出一致反馈。首版目标是可信、可玩的机械体验，不宣称工程级仿真精度。

## 2. 体验差距与改进方向

| 维度 | 此前观察或设计判断 | 改进方向 |
| --- | --- | --- |
| 镜头 | 机器偏小，视角和面板削弱临场感 | 装配环绕、选中聚焦、驾驶跟随、自由缩放 |
| 空间 | 平面移动为主，坡道曾明确标注为视觉占位 | 可通行高差、坡面、桌沿和悬空空间 |
| 结构 | 简化方块不易辨认机械连接 | 合理厚度、轴线、连接件、轮胎、夹指与活动间隙 |
| 材质 | 金属、塑料、橡胶区别不够直观 | 统一尺度下的粗糙度、反射、纹理和适量磨损 |
| 运动 | 运动与驱动、载重之间的关系仍需完善 | 轮子转速、加减速、关节驱动、负载与倾覆反馈 |
| 接触 | 抓取等交互需呈现完整过程 | 靠近、对准、闭合、接触、抬升和释放 |
| 声音 | 缺少已验证的完整机械声音反馈 | 电机、滚动、碰撞、安装和限位反馈 |

这些项目需要逐项复测，不能将此前观察推断为所有窗口或设备上的统一结果。

## 3. 装配工坊：让玩家感觉在工作台前造机器

### 画布与界面

- 中央画布优先，零件库和参数面板可以收起。
- 选零件时仍能看到机器人和目标连接点；避免零件列表把画布推到首屏之外。
- 选中零件后出现局部操作工具与尺寸信息，完整参数按需展开。
- 显示作品名、零件数、保存状态和当前操作；设计信息与游戏资源分区展示。
- 窄窗口改用折叠面板或底部抽屉，控制按钮不遮挡连接位置。

### 镜头与空间判断

- 支持围绕选中部件环绕、平移、缩放、一键查看整机。
- 提供前、侧、顶等标准视角和可选正交视图。
- 安装底部部件时能够查看底部，不因桌面遮挡而无法操作。
- 根据作品包围盒计算取景，避免大机器被裁切、小机器看不清。
- 相机变化保持平缓；提供减少镜头运动选项。

### 装配接触反馈

选取零件 → 半透明预览 → 显示兼容孔位／轴线 → 吸附对齐 → 碰撞检查 → 确认连接。

合法位置明确高亮，不合法位置解释原因。安装声、短暂高亮与连接树更新必须对应同一次成功操作。爆炸视图、剖视与外壳隐藏只改变展示，不修改蓝图结构。

## 4. 试验场：让玩家感觉在驾驶有重量的机器

### 驾驶镜头

- 默认使用第三人称跟随视角，能同时看见机器人与前方操作空间。
- 提供环绕观察、聚焦工具和恢复跟随入口。
- 处理墙体遮挡、近裁剪和急转弯，避免相机穿墙或突然跳动。
- 抓取时允许看清夹指与目标，避免过度景深掩盖接触点。
- 界面保留当前目标和关键控制，其余说明可收起。

### 地形与尺度

第一轮仅做平地、一个坡道、一段桌沿和一个放置平台。地形视觉与碰撞必须匹配，坡道不能只是倾斜外观或占位盒体。

通过螺丝、书本、桌面纹理等熟悉物体表达尺度；机器人、方块、门和坡面使用统一单位。渲染缩放不能悄悄改变物理尺寸。

### 连续运动与物体交互

- 轮子旋转与实际移动速度对应，停止时不空转滑行；需要打滑时由接触状态解释。
- 起步、制动与转向有适度惯性，保持输入响应清楚。
- 关节围绕正确轴线运动，遵守限位、速度和驱动能力。
- 抓取包含接近、对准、闭合、接触与抬升过程；释放后物体重新受环境约束。
- 夹持重物影响重心或驱动负担，不只把物体固定显示在机器旁边。
- 碰墙不能穿过，上坡、滑落与倾覆有可理解反馈，并可快速复位。

可使用适度抓取辅助降低操作门槛，但辅助范围和失败原因应清楚。普通挑战不需要每颗螺丝或每根线缆独立参与物理计算。

## 5. 模型、材质、灯光与声音

### 机械模型规范

按真实功能拆分固定机架、活动关节、轮轴与工具，明确每个活动件的原点和轴线。优先修正尺寸、厚度、活动间隙与连接关系，再添加倒角、螺丝和线缆细节。

每个资源至少对应：视觉模型、简化碰撞形状、连接点、质量参数、材质和可活动部件。建立统一单位、朝向及命名约定，导入后验证尺寸与原点。

### 材质与光照

- 金属、塑料与橡胶分别调节反射和粗糙度，避免仅改变颜色。
- 纹理尺度匹配物体尺寸；磨损集中在接触和使用部位。
- 保留温暖主光和柔和环境光，通过接触阴影表现落地、叠放与夹持。
- 控制曝光与高光，确保深色机架和浅色外壳都有可辨认细节。
- 后期效果作为补充，不能依靠强烈模糊或泛光掩盖模型问题。

### 声音反馈

电机声随运行状态和负载变化；滚动声与速度、地面接触对应；碰撞根据材质与强度区分。安装、限位、抓取成功和释放使用克制的反馈声。

提供主音量与静音；声音关闭后仍可通过画面和提示理解状态。为重复接触设置触发阈值和间隔，避免碰撞声连续轰鸣。

## 6. 技术组织与状态边界

继续围绕既有蓝图、编辑器和试验场拆分职责，具体物理库选择沿用机架方案中的原型验证流程，不在本文直接锁定新依赖。

| 模块 | 职责 |
| --- | --- |
| 蓝图与资源定义 | 零件实例、连接、尺寸、资源和驱动配置的统一来源 |
| 编辑状态 | 草稿、选择、操作历史、保存检查点 |
| 相机控制 | 装配／驾驶模式、聚焦、跟随、遮挡处理 |
| 模拟 | 固定步进、碰撞、关节、驱动、抓取与复位 |
| 渲染同步 | 将模拟状态映射到模型，避免动画与物理争夺同一位姿 |
| 反馈 | 根据实际事件播放声音、提示和高亮 |

固定连接可合并为刚体，活动部分单独模拟；精细视觉模型与简化碰撞分开。模拟快照不得覆盖装配草稿，进入试验场必须使用明确的蓝图版本。

建议调试模式提供碰撞形状、关节轴、重心、支撑范围、速度与帧耗时显示，默认不占据玩家界面。

## 7. 最小可玩验证场景

只做一段完整体验：**自己组装四轮机械臂 → 开上斜坡 → 夹起方块 → 倒车放回工作台。**

体验全程能够看见轮子、关节、夹指和负载变化，相机清楚跟随，物体接触可信。第一轮先保证这一段成立，再扩展房间与关卡。

两次结构对比：

1. 短臂够不到目标，加长后可以够到。
2. 长臂搬重物容易前倾，调整轮距或配重后改善。

这些对比必须由实际结构与运行产生，不能仅用文本提示模拟结果。

## 8. 实施优先级

| 阶段 | 工作 | 退出条件 |
| --- | --- | --- |
| P0：作品可靠 | 修复模板覆盖、保存与试验场不一致 | 整机原样保存、刷新和进入试验场 |
| P1：看清空间 | 画布布局、整机取景、跟随和工具聚焦、统一尺度 | 玩家看清结构、前方路径与接触点 |
| P1：运动可信 | 接地、坡面、关节、抓取、负载与复位 | 最小验证场景可以完整操作 |
| P2：表现统一 | 机械细节、材质、阴影、电机和接触声音 | 表现与实际行为同步，不妨碍判断 |
| P2：扩展挑战 | 高差、桌缝、移动障碍和多解任务 | 玩家愿意修改机器再次尝试 |

不以扩大地图或增加零件数量替代核心体验验收，不承诺未经测量的开发周期或全设备帧率。
