# 小小工坊：自由装配与物理挑战改造方案

- 日期：2026-09-21
- 状态：设计提案，作为后续实施与验收依据；本文中的新增能力尚未实现。
- 范围：将现有固定配件式游戏升级为自由装配、即时试验、多解挑战的桌面机器人游戏。
- 核心交付：自由装配台 + 试验场 + 一个至少支持三种结构解法的任务。

## 1. 改造背景与目标

玩家反馈当前版本缺少乐趣，装配页面不能自由组合。问题集中在玩家无法决定机器的结构，装配对行动结果的影响有限，任务流程重复。

本轮改造围绕以下循环展开：

> 产生想法 → 拼出机器 → 立即试验 → 看见失败原因 → 修改结构 → 完成挑战 → 保存自己的作品。

验收的核心是：玩家能用同一批零件造出形态和行为不同的机器，并愿意为改善表现主动修改设计。任务数量、零件数量和界面精美程度不能代替这一目标。

### 1.1 本轮范围

- 可重复放置的零件实例、空间位姿、连接点和连接关系。
- 直接在三维场景中选择、移动、旋转、连接、拆卸零件。
- 建造与驾驶快速切换，支持恢复试验前状态。
- 可观察的重量、支撑、碰撞和抓取范围反馈。
- 根据目标结果判定成功的开放任务。
- 多份蓝图与现有存档兼容。

### 1.2 后续范围

- 更多环境、竞速、复杂关节和自动化逻辑。
- 作品社区、分享与多人协作。
- 更丰富的伙伴成长与剧情。
- 游戏作品到真实工程设计的显式转换工具。

首轮不做大地图、多人联网、交易市场和全面工程仿真。物理引擎选型与性能上限需通过技术原型验证，本文不预先承诺某个引擎或开发工期。

## 3. 当前实现与差距

截至本文编写时，项目已具备工坊、改装、委托、伙伴、图鉴五个入口；支持左右机械臂独立装卸、先转向再移动、任务暂停与恢复、奖励结算和本地存档。

| 当前实现 | 对体验的限制 | 改造方向 |
| --- | --- | --- |
| `equipped` 保存零件类型 ID 列表 | 同类零件无法多实例放置 | 每个安装零件有独立实例 ID |
| 摄像头、机械臂等位于固定位置 | 拖动落点和旋转不改变机器 | 位姿与连接关系由玩家决定 |
| 固定模型按装备显示或隐藏 | 不能搭四轮车、长臂车等新结构 | 从蓝图实例生成场景结构 |
| 功耗与接口是主要装配约束 | 玩家主要进行数字配平 | 引入位置、支撑与动作范围的因果反馈 |
| 任务预先要求摄像头、机械臂 | 解法在开始前就被指定 | 任务检查目标结果，装备不足给提示 |
| 九乘九网格及拾取状态判断 | 缺少真实接触、运输和结构差异 | 网格用于建造吸附，驾驶与物体交互逐步连续化 |
| 三项任务主要都是取回核心 | 重复操作多，设计问题少 | 挑战分别检验不同结构选择 |

相关代码：

- `src/desktop_robot/game/engine.py`：零件目录、任务、装配约束、动作与 SQLite 存档。
- `src/desktop_robot/studio/static/game/game.js`：页面、装备操作、导航、寻路。
- `src/desktop_robot/studio/static/game/scene.js`：程序化机器人和桌面场景。
- `src/desktop_robot/studio/static/game/motion.mjs`：当前转向移动逻辑。
- `src/desktop_robot/hardware/types.py`：已有工程实例、位姿和关节数据，可借鉴结构。

## 4. 产品定位与模式

保留“温暖的微缩桌面”和“小方伙伴核心”。玩家围绕核心自由搭建身体，可以成为四轮运输车、履带吊车、长臂取物车或固定式机械臂。

### 4.1 自由创造模式

- 提供基础零件自由试装，不先用货币阻挡基础探索。
- 可进入无任务试验场，反复改装、测试和恢复。
- 仍保留连接有效性、碰撞、支撑等直观结构规则。
- 资源数量限制与物理行为分开；无限零件不等于结构不受物理影响。

### 4.2 挑战模式

- 开始前明确目标及预算、尺寸等约束。
- 不强制指定某一套零件作为答案。
- 初次完成获得奖励，重复挑战比较表现与方案。
- 成功标准先以完成目标为主；用时、能耗、损伤等作为可选比较指标，避免唯一最优数值压过创造兴趣。

## 5. 自由装配工作台

### 5.1 布局

- 中央三维场景占据主要区域，直接操作机器。
- 左侧零件库按结构、移动、关节、工具、能源、感知分类。
- 右侧展示当前选中零件、连接状态和必要参数。
- 底部提供建造／试运行切换、撤销／重做、蓝图操作。
- 重心、连接点、抓取范围属于可开启的辅助显示，不常驻堆满画面。

### 5.2 必须支持的操作

| 操作 | 交互结果 |
| --- | --- |
| 拖入零件 | 显示半透明预览、可连接点及有效落点 |
| 移动与旋转 | 改变安装位置和朝向；首版采用吸附与分档旋转 |
| 重复放置 | 同一零件可安装多个，各自独立选择 |
| 零件接零件 | 支持“底盘 → 立柱 → 关节 → 臂杆 → 夹爪” |
| 场景点选 | 高亮实例，显示移动、旋转、复制、拆卸操作 |
| 镜像 | 快速生成对称结构；连接关系一并正确重建 |
| 撤销／重做 | 原子恢复实例与连接关系，失败操作不污染历史 |
| 保存蓝图 | 保存多个命名方案，缩略图辅助辨认 |
| 一键试运行 | 按当前蓝图生成可操控机器 |

手机或窄屏提供“选中零件 → 点击连接点”的替代操作；镜头旋转与零件拖动必须有清晰模式，避免一次拖动触发两个动作。

### 5.3 结构规则

- 零件先通过合法连接点吸附，默认不允许实体穿插。
- 未连接零件可留在编辑暂存区；试运行前提示未接入结构。
- 拆除中间零件时，高亮将失去连接的子结构，并提供整组取下；允许撤销。
- 首版采用以核心为根的连接树，暂不承诺闭环机械约束。
- 左右手臂由安装位置决定，最终统一为可重复使用的臂杆、关节、夹爪等定义；旧的左右臂通过迁移模板保留外观与功能。
- 保留新手预制底盘和臂组件，同时允许拆开、复制和修改。

## 6. 最小零件与行为集合

优先选择能相互组合的少量零件，暂定以下集合，最终数量由原型验证调整：

| 类别 | 首批零件 | 主要用途 |
| --- | --- | --- |
| 核心 | 伙伴核心 | 身份、主控制与结构根节点 |
| 结构 | 板件、连接杆、立柱 | 改变宽度、长度、高度和安装面 |
| 移动 | 单轮、驱动轮模块、履带模块 | 搭建不同底盘 |
| 关节 | 转动关节、伸缩模块 | 改变工具位置与运动范围 |
| 工具 | 夹爪、推板、钩子、货斗 | 抓、推、拖、运输 |
| 能源 | 电池 | 供电与配重 |
| 感知与表现 | 摄像头、表情屏幕 | 辅助观察、伙伴表达 |

钩子拖拽、伸缩和货斗运输必须实现实际接触或约束行为，不能只在 UI 上使用不同名称，底层仍调用同一个拾取开关。

## 7. 物理反馈与操控

### 7.1 首轮必须看得见的因果

| 结构变化 | 预期后果 | 玩家反馈 |
| --- | --- | --- |
| 增大轮距 | 更稳定，但可能无法通过窄门 | 直接碰撞、宽度提示 |
| 加长机械臂 | 抓取范围增加，前倾风险增加 | 抓取范围、重心位置 |
| 电池后移 | 平衡前部载荷 | 重心辅助标记变化 |
| 增加货斗与货物 | 运输容量增加，质量增加 | 载荷变化及操控差异 |
| 改变夹爪朝向 | 可抓取方向变化 | 工具朝向与接触预览 |
| 展开支撑 | 抓取时更稳 | 接地点与倾覆表现 |

以稳定、可预测、易解释为首要目标。几何与动作结果必须一致；无法实现的行为不应通过文案伪装成已有能力。

### 7.2 模拟边界

- 建造模式允许网格吸附；驾驶模式逐步采用连续位置、转向和接触，避免格子规则掩盖结构差异。
- 先验证刚体、固定连接、基础关节和简单抓取；复杂软体、绳索、飞行、破坏延后。
- 使用简化碰撞体，避免直接以高面数外观网格作为碰撞体。
- 核心、底盘与工具的输入映射可视化；玩家应知道哪个按键控制哪组轮子或关节。
- 自动寻路仅作为可选辅助，不能替代试驾，也不能穿过作品实际无法通过的空间。

### 7.3 快速恢复

提供扶正、回到试验起点、恢复试验前蓝图。首次失败无需重新购买零件或长距离返回。展示失败原因，例如“前部载荷导致前倾”“夹爪距离不足”，引导玩家修改结构。

## 8. 试验场与开放任务

### 8.1 无任务试验场

紧邻装配台，放置坡道、台阶、窄门、不同重量的方块和按钮机关。玩家无需领取委托即可进入。

进入试验时保存编辑快照；退出时默认回到该快照。运行中关节姿态和掉落物不自动覆盖蓝图。需要保存运行后姿态时使用显式操作，并进行结构校验。

### 8.2 首个多解任务：从抽屉缝里取出方块

**目标**：将指定方块送入接收区域并稳定停留。

不要求机器人必须安装摄像头或夹爪，也不要求必须进入抽屉。

候选解法：

1. 窄车进入抽屉，通过推板或货斗取出。
2. 长机械臂在抽屉外夹出方块。
3. 钩子从外侧拖出方块。
4. 搭斜坡或调整工具高度后取出。

首轮验收至少实现前三类中的三种可实际操作的解法；若某种机制未完成，必须替换为另一种真实可行且结构明显不同的解法。

任务判定依据物体 ID、所在区域、稳定状态等结果事实。无需检查玩家是否装备预定零件；装备建议只做提示。

### 8.3 后续挑战池

| 挑战 | 设计问题 |
| --- | --- |
| 穿过窄门 | 宽度与零件布局 |
| 从高台取物 | 高度、臂长与稳定性 |
| 搬运三个方块 | 单次抓取与批量运输 |
| 跨越桌面缝隙 | 轮距、长度与桥梁 |
| 按下并保持按钮 | 支撑与动作控制 |
| 运送易碎物品 | 速度、碰撞与稳定性 |

## 9. 技术架构改造

### 9.1 数据分层

将“装备了哪些零件”升级为“每个零件实例的位姿、连接关系及控制绑定”。建议区分：

| 数据 | 职责 |
| --- | --- |
| PartDefinition | 几何、碰撞体、质量、连接点、能源需求、可控制行为 |
| PartInstance | 实例 ID、定义 ID、局部位姿、颜色与可调参数 |
| Connection | 两个实例的连接点、连接类型、关节参数 |
| Blueprint | 根实例、实例集合、连接集合、输入绑定、版本 |
| SimulationState | 世界位姿、速度、关节状态、抓取约束、任务物体 |
| PlayerProgress | 零件解锁、货币、已完成任务、伙伴记忆 |

本文名称和字段是建议契约，实施时应形成实际类型定义和验证规则。

### 9.2 坐标与一致性

- 游戏场景当前使用 Y 向上、机器人局部 +Z 为前；工程轨采用 REP-103（+X 前、+Y 左、+Z 上）。必须通过明确的坐标转换适配器衔接。
- 游戏物理计算统一采用米、千克、秒；编辑器可显示毫米，读写时显式换算。
- 蓝图保存相对父连接的局部变换；模拟保存世界变换，两者不可混用。
- 连接图校验实例存在性、连接点占用、连接兼容、根节点连通性及首版无环限制。
- 结构、外观和碰撞体使用同一蓝图来源，避免画面上装好了、模拟中却没有。

### 9.3 建议模块拆分

在现有目录下逐步拆分，避免继续扩大单一 `engine.py` 和页面脚本：

```text
src/desktop_robot/game/
  parts.py             零件定义
  blueprints.py        蓝图、实例、连接及校验
  missions.py          目标定义与判定
  progress.py          解锁、奖励与成长
  save.py              存档、迁移与事务

src/desktop_robot/studio/static/game/
  editor/              选择、吸附、变换、命令历史
  simulation/          刚体、关节、输入、抓取及恢复
  world/               工坊、试验场、挑战场景
  ui/                  零件库、属性、蓝图与导航
```

目录是实施建议，不要求为了形式拆分已稳定且无关的原有模块。

### 9.4 前后端职责

- 浏览器处理编辑预览、输入及实时模拟，不能继续每移动一格就等待一次 HTTP 请求。
- 后端负责零件目录、蓝图校验、存档版本、进度与奖励事务。
- 单机原型允许客户端提交试验结果，但必须验证任务、运行 ID、蓝图版本和是否重复结算；这不能宣称为权威物理验证或多人防作弊。
- 如未来需要可信排行榜或联网对战，再引入服务端模拟或经过验证的回放机制。
- 保存使用修订号避免多个标签页互相覆盖；保存失败保留本地编辑状态并清楚提示。

### 9.5 保留现有能力

保留 Three.js 场景基础、伙伴护照、对话与记忆、SQLite 事务以及硬件工程工具入口。工程模块的 `instance_id`、位姿、`joint` 等结构可复用设计经验，但游戏数值与真实硬件规格独立维护。

游戏试验不向真机发送指令。游戏蓝图也不能直接标记为可制造或已通过工程验证。

## 10. 状态切换与旧存档迁移

### 10.1 导航必须对应真实状态

- 从试验或任务切回工坊、改装：暂停模拟并保存检查点，开放编辑。
- 继续未修改蓝图的任务：恢复检查点。
- 修改蓝图后继续任务：先验证结构与约束；能安全恢复则继续，否则说明原因并从任务起点重试。
- 避免静默把新结构塞进原位置，引发穿插、物体丢失或无效抓取。
- 恢复策略必须覆盖携带物、关节位置、底盘变化和窄空间中的尺寸变化。

这扩展现有的任务暂停功能，防止再次出现“界面已回工坊，后台仍禁止改装”的状态分歧。

### 10.2 迁移要求

- 提升存档 schema 版本，迁移前备份，事务内执行。
- 将旧 `equipped` 列表映射为带默认位置和连接点的“经典小方”蓝图。
- 保留姓名、伙伴 ID、货币、已拥有零件、任务奖励记录和回忆。
- 旧任务若不能映射到新的模拟检查点，保留已完成进度，并明确提示该次未完成挑战从起点重新开始。
- 迁移可重复执行而不重复赠送、扣除或生成零件。
- 撤销／重做属于编辑历史；任务暂停检查点与编辑历史分开保存。

## 11. 分阶段交付与验收

依赖顺序：结构数据 → 编辑器 → 可运行结构 → 多解任务 → 蓝图与长期体验。P0 的操控与模拟原型可以尽早验证，避免编辑器完成后才发现结构不可运行。

| 阶段 | 优先级 | 交付物 | 退出标准 |
| --- | --- | --- | --- |
| A：结构基础 | P0 | 零件实例、连接图、版本化蓝图与迁移 | 同类多实例、位姿及连接完整保存；旧小方可恢复 |
| B：三维编辑 | P0 | 拖入、吸附、旋转、复制、拆卸、撤销与镜像 | 不填写工程表单即可做出四轮车和长臂结构 |
| C：即时试验 | P0 | 建造／驾驶切换、碰撞、抓取、扶正与恢复 | 改结构后能够立即体验行为差异 |
| D：多解任务 | P1 | 抽屉取物挑战、结果判定 | 同一批零件至少三种明显不同的可行结构 |
| E：作品积累 | P2 | 多蓝图、缩略图、方案比较及成长联动 | 能保存、找回、修改并重复使用作品 |

### 11.1 功能验收清单

- [ ] 一个蓝图可包含至少四个同型号轮子，各自独立选择和保存。
- [ ] 零件拖入不同连接点后，安装位置与实际模拟位置一致。
- [ ] 移动、旋转、复制、镜像、删除均可撤销和重做。
- [ ] 断开的结构不会被静默当作正常整机运行。
- [ ] 加长机械臂能改变抓取范围，改变轮距能改变通过性。
- [ ] 碰撞、支撑和质量至少产生一种可重复、可解释的设计取舍。
- [ ] 试验失败后可以立即扶正或恢复，不需重新购买零件。
- [ ] 摄像头与某一侧机械臂不再是所有任务的强制准入条件。
- [ ] 同一目标由三种结构完成，结算依据结果而非预设零件清单。
- [ ] 修改装配后恢复任务不会出现非法抓取或碰撞穿插。
- [ ] 刷新与重启服务恢复蓝图和进度；重复结算不会重复发奖。
- [ ] 窄屏能完成选取、安装、旋转、删除和开始试验。

### 11.2 体验验收

以下为拟定目标，需要实际试玩验证：

- 新玩家能在简短引导后独立拼出第一台可移动机器。
- 玩家能说清至少一次失败与自己的结构设计之间的关系。
- 同一任务结束后，玩家愿意尝试另一种结构，而不只是领取下一项奖励。
- 玩家感觉主要时间花在创造和试验上，而非页面跳转与确认操作上。

如果这些目标未达到，优先调整拼装交互、反馈和挑战设计，暂停扩大内容规模。

## 12. 测试与风险控制

| 风险 | 验证与处理 |
| --- | --- |
| 物理抖动或机器无故散架 | 先做固定连接和少量关节原型；限制极端质量比与不合法穿插 |
| 自由摆放操作困难 | 默认连接点吸附、旋转预览和清楚的选中状态；提供新手模板 |
| 大量零件造成性能下降 | 简化碰撞体、复用几何与材质；用目标设备测试后确定实例上限 |
| 结构变化对表现没有影响 | 对臂长、轮距、配重等设置可重复的行为对比用例 |
| 任务仍只有一种实质解法 | 用三份不同结构蓝图验证同一目标，不以三个外观变体充数 |
| 数据迁移丢失奖励或蓝图 | 备份、版本迁移、幂等测试、失败回滚 |
| 任务恢复与装配状态不一致 | 覆盖导航、刷新、多标签页、改装后恢复、携带物恢复 |
| 只完成视觉原型 | 验收必须通过实际驾驶、接触、运输与任务结算 |

自动化测试优先覆盖连接图、变换、撤销、迁移、状态切换和奖励幂等；物理行为结合确定场景的重复试验与浏览器实操。仅有单元测试通过不能证明游戏好玩，需保留真实试玩验收。

## 13. 下一步实施入口

首先完成阶段 A 的数据契约与一个小型物理原型：用同一组板件、轮子、连接杆、电池和工具，生成两种结构，验证结构改变能否改变抓取范围、碰撞或稳定性。

原型成立后再推进正式编辑器，并始终围绕首个多解任务选择功能。保留现有温暖美术方向，把研发重点放在玩家能够决定什么、试验能够反馈什么。
